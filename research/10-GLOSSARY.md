# Glossary and academic terminology

Use **academic terms in the paper**. “AI Business Analyst” is allowed in the title/subtitle if paired with a precise term.

## Preferred paper terms

| Use this | Avoid as primary |
|----------|------------------|
| Agentic Requirements Engineering | “Our GPT bot” |
| Conversational requirements elicitation | “Chatbot for SRS” |
| Requirement Decision / requirement critique | “The AI didn’t like it” |
| Stakeholder validation loop | “User said OK” |
| Structured specification / project model | “The document” |
| Traceability | “We remember the chat” |

## Search terms (literature)

- LLM-based Requirements Engineering (LLM4RE)
- AI-assisted / automated requirements elicitation
- Agentic Requirements Engineering
- LLM-based requirements analysis / specification / validation / management
- Interactive / interview-based elicitation
- User story generation and quality (QUS)
- Knowledge-augmented RE / RAG for RE
- Requirements traceability with LLMs

## Metric short names

| Acronym | Meaning | From |
|---------|---------|------|
| IRE | Implicit Requirement Elicitation (ratio) | ReqElicitGym / OntoAgent |
| TKQR | Turn-discounted Key Question Rate | OntoAgent |
| QUS | Quality User Story framework | Lucassen et al.; used in TSE 2026 |
| AQUSA | Automatic QUS syntactic checker | prior tool |
| P/R/F1 | Precision / recall / F1 | Yin, RECOVER, … |
| κ | Cohen’s kappa | TSE quality study; ReqElicitGym |
